# 배달 게임 그래픽 구성

게임 경로와 배포는 기존 `/games/delivery`를 사용합니다. 홈의 스타일과 글꼴은 변경하지 않습니다.

## 시각 기준

- 참고 이미지의 맑은 낮 분위기: 푸른 하늘과 흰 구름, 크림·민트·연보라 외벽, 청록색 유리, 청회색 도로와 따뜻한 석재 보도. 화면 전체 색상 필터는 사용하지 않습니다.
- 브랜드 상품과 간판은 배경보다 명확한 색과 큰 문구로 표시합니다.
- 건물은 겹친 창틀·창턱, 사선 유리 반사 무늬, 얇은 층별 띠·모서리 기둥, 줄무늬 차양과 일부 얕은 발코니로 마감합니다. 2026-10-15 상가 거리 개선에서 실제 벽체 높이 1.8배·전면 폭 1.3배를 적용했습니다. 창문·문 크기는 유지하고 3~4층 창문 줄을 추가했습니다.
- 접지 그림자와 건물 전용의 약한 햇빛 그림자는 공유한 작은 텍스처를 사용합니다. 실시간 그림자, 실시간 반사, 후처리 효과는 쓰지 않습니다. 구름은 공유 재질의 불투명한 도형을 묶어 그립니다.
- 3차선 중심선과 장애물 위치는 `laneSpacing`을 함께 사용합니다. 광고 버스는 `busLaneOffset`으로 분리된 차로를 사용합니다.

## 수정 위치

- `components/delivery/three/scene-art.ts`: 공통 색상, 건물·나무·가로등·자전거·배달원 형태.
- `components/delivery/three/scene-builders.ts`: 도로·간판·버스·목적지의 조립과 텍스처 연결.
- `components/delivery/three/scene-layout.ts`: 옥외 설정의 좌표/비율 변환, 건물 확대 비율(폭 1.24 / 높이 1.27 / 깊이 1.18, 직전 디자인 대비 약 7~8% 확대), 간판 크기·높이·정면 방향, 광고 앞 조경 여백, 세로 화면의 최소 가로 시야각(43도).
- `components/delivery/three/street-layout.ts`: 상가 건물의 추가 높이·폭 배율, 외곽 간격, 보도 이격, 고정 배치 생성. 기존 기본 배율 위에 벽체의 높이·폭만 조정하므로 문·창문은 늘어나지 않습니다. 경로/카메라/충돌 코드와 분리되어 있습니다.
- `components/delivery/DeliveryScene3D.tsx`: 카메라, 하늘, 조명, 거리별 표시 범위, 자원 해제.
- `components/delivery/DeliveryGame.module.css`: 게임에만 적용되는 화면과 조작 버튼.
- `public/games/delivery/brands/`: 로고·상품·패키지·간판·버스·옥외 광고 SVG. 기존 경로를 유지해 그림을 교체할 수 있습니다.

정적인 모델은 재질별로 묶어 그립니다. 기본 도형·재질·그림자 텍스처와 건물 타입별 템플릿을 공유합니다. 상가 외관은 경로 36m 단위 블록으로 다시 묶어 기존 거리 컬링을 적용합니다. 전체 건물을 매 프레임 다시 만들지 않으며, 재시작 시 새 월드를 만들지 않습니다.

## 모바일 광고 시야 — 교체형 옥외 광고

- 현행 광고 설정은 `data/delivery-outdoor-ads.ts` 한 곳에 모여 있습니다. 1:1, 9:16, 16:9, 4:1 광고면을 정확한 비율로 사용하며 건물/거리/버스 광고의 기본 문구는 ‘광고주 구함’입니다.
- 가로형·정사각형을 중심으로 13곳을 띄워 배치하고, 세로형은 돌출 간판·정류장, 긴 배너는 옥상에 배치합니다. 기본 일반 주행 표본에서 읽을 수 있는 고정 광고는 최대 두 개입니다. 도로 위 게이트는 사용하지 않습니다.
- 광고의 문구/이미지는 밝은 크림색 면 안에 표시하고, 초록 테두리·작은 조명은 그림 밖에 둡니다. 교체 이미지의 종횡비가 달라도 전체 그림을 유지합니다.
- 광고 설정에서 실제 모델 위치/크기/회전을 결정합니다. 가까워진 광고가 화면 가장자리로 나가는 자연스러운 원근 이동은 유지하며, 모든 면이 보이는 접근 구간을 모바일 네 비율에서 검사합니다.
- 광고 시야 때문에 필요한 건물만 뒤로 물리고, 시선에 걸리는 나무·가로등은 제외합니다. 옥외 개편 후 일반 건물은 201개이며 기존 3~4층 스타일·기본 밀도를 유지합니다.
- 자전거의 선택 브랜드·배달함·상품 그림은 별도 경로를 사용하며 옥외 광고 변경에 영향받지 않습니다.
- 상세 위치/이미지 교체/검증/재배포 방법: [옥외 광고 가이드](delivery-outdoor-ads.md).

현재 배달원은 직접 구성한 임시 캐릭터이며 공식 쿵야 모델이 아닙니다. `replaceable-delivery-rider` 그룹을 정식 모델로 교체할 수 있습니다. 실제 상품과 캐릭터 도입 시 해당 에셋과 저사양 실기기 성능 검수가 필요합니다.

## 간결한 주행 화면

- 상단에는 방향 아이콘, 한 줄 행동 안내, 목적지, 해당 안내 지점까지의 거리만 표시합니다. 하단의 얇은 선은 전체 경로 진행도이며 상품 전달 중에는 전달 진행도를 보여줍니다.
- 큰 배달 안내 카드를 없애고 같은 상단 영역에서 입구·후진·우회·정차·전달·완료를 안내합니다. 문구가 바뀌어도 상단 높이와 조작 버튼 위치는 변하지 않습니다.
- 하단 버튼 띠는 없애고 주행 화면을 터치한 위치에 반투명 조이스틱 하나를 표시합니다. 손을 놓으면 숨기며 상단 길안내·일시정지 영역은 조작에서 제외합니다. 보조 설명, 속도계, 현재 차선·이동 거리, PC 단축키 문구는 주행 화면에 표시하지 않습니다. 스크린리더용 이름·조작 설명과 PC 화살표 입력은 유지합니다.
- 중복 상품 정보 띠는 없앴으며 선택 브랜드는 기존 자전거 뒤 배달 상자, 앞바구니, 시작·퀴즈·완료 화면에 그대로 남습니다.
- 참고 이미지에 맞춘 아이보리 UI와 짙은 녹색 길안내를 유지합니다. 조이스틱은 옅은 민트색 반투명 바탕과 조금 더 선명한 손잡이로 구성합니다. 화면 경계를 넘는 원은 주행 화면 안으로 잘라 길안내를 가리지 않으며, 원 밖의 드래그도 계속 인식합니다. 기존 하단 띠의 공간은 도로에 돌려주되 카메라 설정·추적 방식은 바꾸지 않습니다.
- 안내 우선순위는 `components/delivery/delivery-navigation.ts`, 상단 모양은 `.navigationHud` 스타일에서 관리합니다. `scripts/test-delivery-navigation.ts`로 상황별 안내를 확인할 수 있습니다.

## 참고 이미지 적용 범위

참고 이미지 적용은 색감·건물 외관·광고판·UI 마감에 한정했습니다. 후속 조이스틱 변경에서도 경로·진입로·차선 규칙, 광고 배치 설정, 카메라 추적과 시야각 설정, 자전거·캐릭터 모델, 퀴즈·배달 완료 흐름은 유지합니다. 참고 이미지의 사진처럼 정교한 렌더링을 그대로 복제하는 대신 기존 경량 3D 도형과 공유 재질로 분위기를 적용합니다.

## 2026-10-15 건물 크기·밀도 변경 기록 (옥외 광고 개편 전)

- 최신 참고 이미지는 건물 비례와 밀도에만 적용했습니다. 색상·UI·조이스틱·자전거/캐릭터·카메라/FOV·도로·주행/충돌·배달은 변경하지 않았습니다.
- 일반 건물의 실제 모델 외곽(게임 공간 단위): 높이 6.53~13.11 → 10.79~21.74, 전면 폭 7.34~8.77 → 9.36~11.08. 지붕·창틀·발코니를 포함한 값이며 벽체 자체 배율은 각각 1.8, 1.3입니다. 목적지의 기존 주택은 보존합니다.
- 기존은 중심 간 32m 고정 배치 후 광고 구간 건물을 제거했습니다. 이제 인접 건물의 플랫폼·처마·발코니까지 포함한 외곽 사이를 전면 폭의 15% 기준으로 배치합니다. 일반 구간 실측 간격은 1.41~1.97(15.0~18.6%). 커브 샘플 오차를 포함하며 광고 시야/진입로 등의 예외는 별도입니다.
- 보도 바깥선은 중심에서 10.1, 전면 기본 여유는 0.55입니다. 실제 모델 외곽과 곡선 도로·보도·진입로의 거리를 검사해 추가 이격합니다. 넓어진 지붕은 깊이 방향으로 같이 커지지 않도록 구성했습니다.
- `pnpm exec tsx scripts/test-delivery-street.ts`: 실제 모델 외곽·배율, 템플릿 공유, 건물끼리/광고와 겹침, 도로·보도·진입로·배달 주택 공간, 주요 광고 시야, 일반 외곽 간격을 검사합니다.
- `pnpm exec tsx scripts/test-delivery-art.ts`: 11개 광고의 네 모바일 캔버스 비율에서 접근 시 전체 표시 구간과 픽셀 크기를 검사합니다.
- `scripts/qa-delivery-street.mjs`: 실제 앱에서 42/125/242/410/475/600(왼쪽 우회)/850m 및 360/390/430px 화면을 촬영합니다. 테스트 브라우저의 런타임 위치만 고정하며 제품 코드에 테스트 훅은 넣지 않습니다. 수정 전후 모두 같은 위치·중앙 차선·정지 상태·움직임 줄이기 설정으로 동일 카메라 목표를 사용합니다.
- 수정 전은 `STREET_QA_PHASE=before`, 이후는 `after`로 실행합니다. `test-artifacts/streetscape/`에 화면과 결과를 저장하며, 이후 검사는 보호한 파일/함수의 SHA-256도 비교합니다. 이번 변경과 무관한 퀴즈·완주·조이스틱 전체 테스트는 반복하지 않습니다.
- 데스크톱 브라우저의 모바일 뷰포트 검증이며 실제 저사양 휴대전화의 FPS를 보증하지 않습니다.
