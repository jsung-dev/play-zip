# 배달 길 안내 UI

주행 입력·카메라 설정·충돌·정지 후 퀴즈는 기존 구현을 사용합니다.
배달 골목 세 곳만 기존 입구에 짧은 출구를 연결한 통과형 경로입니다.
하단 안내 카드/팝업은 없으며 조이스틱의 영역도 그대로입니다.

## 골목 전용 추가 차선 / 재방문

- `delivery-turns.ts`에서 각 골목의 입구·출구를 실제 교차로로 조회합니다. 안내 대상 번호나 완료 여부는 진입 제한으로 사용하지 않습니다.
- 기존 세 차선은 모두 직진용입니다. 각 골목 입구 전 40m에만 같은 쪽 바깥으로 회전 전용 차선을 추가했습니다. 그 앞 12m는 넓어지는 테이퍼입니다. 출구 쪽에도 반대 방향 진입과 전진 합류를 위한 같은 연결이 있습니다.
- `data/delivery-map.ts`의 `TURN_LANE`와 `TURN_LANE_CONNECTIONS`가 노면·입력·진입의 공통 기준입니다. 일반 차선 중심은 -2.5 / 0 / 2.5, 추가 차선 중심은 -5 또는 5입니다. 도로 중심 경로·기존 세 차선 폭·인도는 유지합니다. 광고 버스는 같은 쪽 추가 차선 구간을 사용할 수 없습니다.
- 좌우 한 번에 인접 차선 하나만 0.26초 동안 이동합니다. 가운데에서 골목에 들어가려면 바깥 일반 차선, 추가 차선 순으로 두 번 조작합니다. 한 차선 이동 도중 입력을 연타해 여러 차선을 건너뛰지 않습니다. 가운데·기존 바깥 차선에서는 자동으로 골목에 들어가지 않습니다.
- 추가 차선의 실제 자전거 위치가 경계를 넘었을 때만 골목 곡선으로 이어집니다. 목표 차선 값만으로 진입하지 않습니다. 멈춰 있으면 아무 이동도 일어나지 않습니다. 출구의 추가 차선은 12m 테이퍼에서 큰길 바깥 차선으로 이어지며 위치를 순간적으로 옮기지 않습니다.
- 안내는 `왼쪽 회전 차선` / `오른쪽 회전 차선`, 진입 차선에 있으면 `골목으로 진입`입니다. 추가 차선과 골목 노면에 민트 화살표를 표시하며 하단 카드나 팝업을 추가하지 않습니다.
- 접합부 첫/마지막 6m 노면 폭 최대 7.6, 골목 내부 폭 4.4를 유지합니다. 모바일에서 추가 차선의 자전거가 화면 밖으로 잘리지 않도록 추가된 폭만큼 카메라의 좌우 추적 위치를 보정합니다. 기존 세 차선에서의 카메라, 높이·각도·FOV는 그대로입니다.
- 전진할 때는 앞쪽 입구, 후진하여 돌아올 때는 출구 교차로로 진입할 수 있습니다. 뒤에서 진입해도 카메라 시점은 뒤집지 않습니다. 원래 입구까지 돌아온 뒤 전진으로 재진입하는 것도 가능합니다.
- 미완료 집을 재방문하면 해당 집의 퀴즈·배달을 다시 활성화합니다. 완료 집도 길은 열려 있지만 퀴즈나 완료 수는 중복 처리하지 않습니다. 이동 방향에 맞춰 추천 대상만 바뀝니다.
- 손을 놓으면 기존 감속으로 멈춥니다. 일시정지·창 포커스 이탈 시 입력은 해제하지만 실제 차선 위치는 유지합니다. 회전 예약은 더 이상 사용하지 않습니다. 재시작하면 가운데 차선으로 초기화합니다.

## 좌표의 출처

- 목적지 ID/순서/방향: `data/delivery-map.ts`의 `DELIVERY_STOPS`.
- 건물: `scene-builders.ts`의 `delivery-house-${stop.id}`. 첫 집은 `stop-01`, 포근빌라 202호, 왼쪽 골목의 주황 지붕 집입니다.
- 실제 문: `scene-art.ts`에서 문 모델과 함께 저장한 `entranceLocal`을 건물의 배율·회전·월드 위치로 변환합니다. 화면 좌표나 옆 상가 위치를 사용하지 않습니다.
- 첫 집의 문 중심 월드 좌표: `[-35.2637, 1.6510, -288.9281]`. 출구를 막지 않도록 해당 배달 집만 정차 구역 바깥쪽으로 옮겨 문이 골목을 향하게 했습니다.
- 이동 안내: 메인 도로 → `getDrivewayFrame()`의 골목 → 배달 구역 → 출구 → 같은 쪽 큰길 차선. 도로 렌더링과 실제 주행이 같은 곡선을 사용합니다.
- 세 집의 정차 구간은 현재 `18.5895~26.5895m`, 폭은 기존 `4.4`입니다. 추가 차선 접합점이 바깥으로 이동해 곡선상의 누적 길이만 달라졌으며 집·배달 구역 중심의 실제 위치는 유지했습니다. 바닥 표시와 도착 판정 모두 `getDrivewayDeliveryInterval()`을 사용합니다.
- 출구는 입구보다 큰길 경로상 38m 앞에 연결됩니다(`DRIVEWAY_ROUTE.exitAdvance`). 전체 큰길·우회로·FOV·카메라 높이는 그대로입니다. 출구 접합부에서는 기존 카메라 레일로 부드럽게 복귀합니다.
- 골목 전용 전진 6/후진 4 제한과 막다른 끝 자동 제동을 제거했습니다. 큰길과 동일한 전진 20/후진 8 및 가감속 설정을 사용합니다. 충돌 감속 1초와 수동 정지는 유지합니다.

## 경유지 통과와 완료 수

- 안내 대상(`stopIndex`), 퀴즈 통과(`quizPassedStops`), 실제 배달 완료(`completedStops`), 미배달 통과(`skippedStops`)는 별도입니다.
- 배달 구역에서 직접 정차하면 퀴즈가 열립니다. 정답을 누르는 같은 처리에서 즉시 완료 목록·완료 수·`배달 완료!` 표시를 갱신합니다. 기존 정답 후 1.6초 추가 대기는 제거했습니다. 오답 재시도, 동일 집 중복 완료 방지, 최종 목적지 전달·광고 흐름은 유지합니다.
- 큰길에서는 해당 골목 **출구보다 6m 더 지나면** 미배달 통과 처리합니다. 골목 안에서는 **배달 구역 끝보다 6m 더 지나면** 처리합니다. 조금 벗어난 동안에는 후진해서 정차 위치를 보정할 수 있습니다.
- 통과 처리는 다음 대상으로 안내를 넘길 뿐 완료 수를 올리지 않습니다. 돌아가도록 강제하지 않지만, 원하면 다시 방문할 수 있습니다. 실제 배달을 완료하면 미배달 통과 목록에서도 제거합니다.
- 최종 목적지는 경유 완료 여부와 무관하게 기존 전달 애니메이션 후 종료합니다. HUD/결과는 실제 경유 배달 수 + 최종 전달 1건만 표시합니다(최종만 배달하면 `1 / 4`).
- 기존 큰길 공사 구간의 우회 선택은 유지합니다. 공사 바리케이드를 직진으로 뚫는 변경은 아닙니다.

## 표시 기준

현재 배달할 건물의 지붕 위에만 `배달할 집`을 표시합니다. 골목 진입 후 문까지 가까워지고, 카메라 시야·문 정면 방향·가림 검사를 통과하면 실제 문에 `배달 입구`를 표시합니다. 화면 밖 좌표를 가장자리로 강제 고정하지 않습니다. 가장자리에서는 라벨 정렬만 바꾸며 핀 끝은 동일한 월드 좌표에 남습니다.

바닥 화살표는 최대 3개를 재사용하며 실제 곡선을 따릅니다. 지나간 화살표는 다음 구간으로 이동하고, 배달 후에는 큰길로 나가는 방향으로 표시됩니다. 이전 집의 목적지 핀/링은 다음 배달로 넘어갈 때 해제됩니다.

상단 거리의 기준은 **현재 경로를 따라 배달 도착 구간까지**입니다. 골목 입구까지의 거리와 섞지 않습니다. 이전 골목에서 나오는 거리와 막힌 길에서 돌아가는 거리도 포함합니다.

일시정지 메뉴의 `길 안내` 버튼은 기존 일시정지를 해제하고 기존 렌더링 루프에서 4초간 표시를 조금 강조합니다. 별도의 이벤트 리스너나 타이머를 추가하지 않으며, 일시정지 중에는 강조 시간도 멈춥니다. 브랜드·진행은 초기화하지 않습니다.

## UI / 검증

- 상단: `DeliveryNavigation.module.css`; 기존 캔버스 상단 75px 기준을 보존해 카메라/FOV를 변경하지 않습니다.
- 일시정지: `DeliveryPauseMenu.tsx`; 기존 캠페인 공통 흰 카드/버튼 스타일을 재사용합니다.
- 계산: `delivery-guidance.ts`, `delivery-navigation.ts`.
- 3D 표시: `three/route-guidance.ts`.
- 계산/좌표 검사: `npx tsx scripts/test-delivery-navigation.ts`, `npx tsx scripts/test-delivery-guidance.ts`.
- 브라우저 검사: `node --import tsx scripts/qa-delivery-guidance.mjs`. 접근 위치만 테스트 상태로 준비한 뒤 세 골목의 진입·직접 제동·퀴즈·전진 출구는 실제 입력으로 확인합니다. 터치로 골목을 지나친 경우, 큰길 미방문, 4/4와 1/4 종료, 충돌 감속 복구, 재시작도 확인합니다. 실물 휴대폰 전체 경로 테스트나 성능 측정 결과는 아닙니다.
- `GUIDANCE_QA_PARTIAL=1`은 첫 경유지를 놓친 뒤 두 번째만 배달하여 `2 / 4`로 종료하는 추가 검사입니다.
- 현재 차선 변경 검증은 `GUIDANCE_QA_LANES=1`을 사용합니다. 일반 차선 직진 → 놓친 집으로 후진 재방문 → 추가 차선 진입 → 정답 즉시 완료 → 전진 출구/합류, 모바일 터치, 최종 광고·재시작을 검사합니다. 과거 `GUIDANCE_QA_TURNS` / `TURN_VISUAL` 플래그는 이전 회전 예약 방식 기록이며 현재 동작의 검증으로 사용하지 않습니다. 계산 검사는 `scripts/test-delivery-turns.ts`입니다.
- 결과/캡처: `test-artifacts/guidance-ui/` (Git 제외).
